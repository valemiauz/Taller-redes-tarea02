  LEVEL 02 — LORE
  
📜 El Protocolo (Teoría)

  

    
PostgreSQL usa un protocolo de capa de aplicación orientado a mensajes. Nació del proyecto
    POSTGRES de Berkeley (1986); la versión 3.0 (2003, PostgreSQL 7.4) fijó la estructura que sigue
    vigente. Cada mensaje (salvo los primeros) tiene 3 campos:

    

      
🏷TIPO (1 byte)
Un carácter ASCII que identifica el mensaje.

      
📏LONGITUD (4 bytes)
Entero Big-Endian con el tamaño total.

      
📦PAYLOAD
El contenido: SQL, filas, credenciales...

    

    
🎮 Máquina de estados: las 4 fases de una partida

    
    
      
  • 1. Conexión
    SSLRequest → el server responde N (sin TLS) → StartupMessage.
    • 
      
  • 2. Autenticación
    SCRAM-SHA-256: se intercambian nonce, sal e iteraciones. La contraseña nunca viaja.
    • 
      
  • 3. Preparación
    ParameterStatus, BackendKeyData y ReadyForQuery (Z).
    • 
      
  • 4. Consultas
    Query (Q) → RowDescription, DataRow, CommandComplete → Terminate (X).
    • 
    

  


  
📄 Bestiario de mensajes (clic en una fila = +10 pts)

  LEVEL 05 — SCAN
  
🔍 Tráfico Observado

  

    
Con el filtro pgsql en Wireshark se confirmó la máquina de estados exacta.
    Hallazgo clave para la seguridad:

    
⚠ Sin TLS, TODO el SQL y los datos viajan en
    texto plano. La única excepción es la contraseña, protegida por SCRAM.

    
Secuencia de una consulta SELECT

    
# Cliente -> Servidor
Q  Query           SELECT * FROM tareas;
# Servidor -> Cliente
T  RowDescription  (id, nombre_ramo)
D  DataRow         [1, "Taller de Redes"]
C  CommandComplete SELECT 1
Z  ReadyForQuery   listo ✅

  







  LEVEL 06 — BOSS FIGHT
  
⚔ Las 3 Modificaciones (MITM en vivo)

  

    
Con NetfilterQueue + Scapy, scapy_mitm desvía el tráfico del puerto 5432 a una
    cola, lo reescribe y lo reinyecta. Regla de oro: sustituciones de igual longitud para no
    romper la conexión TCP. ⚔ Pulsa ATACAR para derrotar a cada jefe.

  


  

    
👿

    

      DENEGACIÓN DE SERVICIO
      
BOSS 1 — "El Terminador" (Q → X)

      
Cambia el byte de tipo Q (Query) por
      X (Terminate). El servidor cree que le piden cerrar y mata la sesión.

      
HP 100%

      

      
EFECTO: psql: "server closed the connection
      unexpectedly". Valida el Caso A.

      
    

  


  

    
🤖

    

      CONSULTA ALTERADA
      
BOSS 2 — "El Impostor" (tareas → xareas)

      
Reescribe el texto SQL en tránsito. Tú escribes tareas,
      el server recibe xareas.

      
HP 100%

      

      
EFECTO: El servidor ejecuta OTRA consulta:
      relation "xareas" does not exist.

      
    

  


  

    
👻

    

      DATOS FALSIFICADOS
      
BOSS 3 — "El Falsificador" (DataRow adulterado)

      
Modifica la respuesta del server:
      Taller de Redes → HACKED de Redes.

      
HP 100%

      

      
EFECTO: psql muestra un dato que nunca existió
      en la BD. Ni cliente ni servidor lo detectan. Valida el Caso B.

      
    

  







  LEVEL 07 — CHAOS
  
🎲 Las 2 Inyecciones (Fuzzing)

  

    
Desde scapy_attacker se hace el handshake TCP a mano y se inyectan
    StartupMessages malformados. Sorpresa: aquí el objetivo NO es tumbar al server, sino comprobar
    que su parser valida bien y rechaza la basura.

  

  

    

      📐INJECT 1: FRAMING
      
Aleatoriza el prefijo de longitud (0, 0xFFFFFFFF, millones...).

      
✅ El server rechaza: "invalid length of startup packet".

    

    

      🃏INJECT 2: CONTENIDO
      
Versión de protocolo y parámetros con bytes aleatorios.

      
✅ ErrorResponse: "unsupported frontend protocol".

  LEVEL 10 — GAME CLEAR
  
🏆 Conclusión

  

    
La autenticación de PostgreSQL (SCRAM-SHA-256) es robusta: la contraseña nunca
    viaja. PERO sin TLS, todo lo demás es manipulable por un atacante en la ruta:

    
✅ Se logró denegar el servicio, ejecutar consultas falsas y falsificar datos
    ante el cliente. El fuzzing confirmó que el parser de inicio del server sí valida las entradas.
    Las métricas fijaron cotas concretas: ~200 ms de latencia y ~10% de pérdida.

    
⚠ Moraleja: en producción, TLS no es opcional.
